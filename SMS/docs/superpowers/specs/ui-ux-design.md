# SMS Link - UI/UX 设计规范 v2.0

> **设计理念**: 温暖友好、简洁直观、跨平台一致性
> **目标用户**: 普通用户，个人使用场景
> **更新日期**: 2026-04-10

## 1. 架构概览

### 1.1 技术栈
- **UI 框架**: Flutter 3.x + Dart（跨平台支持：Android、iOS、Desktop）
- **设计系统**: Material 3 + 自定义温暖主题
- **状态管理**: Riverpod 2.x
- **路由**: go_router 13.x
- **通信层**: Platform Channel（与现有 Kotlin 模块通信）
- **本地存储**: Hive / SQLite（通知历史、文件传输记录）

### 1.2 设计系统（基于 UI/UX Pro Max 推荐）

**视觉风格**: 温暖友好 + 极简现代

**配色方案**:
- Primary: `#2563EB` (温暖蓝色)
- Secondary: `#3F3F46` (中性灰)
- Background: `#FAFAFA` (浅灰背景)
- Surface: `#FFFFFF` (卡片白色)
- Text Primary: `#09090B` (深黑)
- Text Secondary: `#71717A` (中灰)
- Success: `#10B981` (绿色)
- Warning: `#F59E0B` (橙色)
- Error: `#EF4444` (红色)

**字体系统**:
- Heading: `Caveat` (手写风格，温暖友好)
- Body: `Quicksand` (圆润易读)
- 字重: 300 (Light), 400 (Regular), 500 (Medium), 600 (SemiBold), 700 (Bold)

**圆角规范**:
- 小组件: 8dp
- 卡片: 16dp
- 按钮: 12dp
- 底部导航栏: 24dp (顶部圆角)

**间距系统**:
- xs: 4dp
- sm: 8dp
- md: 16dp
- lg: 24dp

- 2xl: 48dp

### 1.3 架构方案
Flutter 作为独立应用，通过 Platform Channel 调用现有 Android 原生模块：

```
┌─────────────────────────────────────┐
│         Flutter UI Layer            │
│  (Material 3 + Riverpod + Router)   │
└──────────────┬──────────────────────┘
               │ Platform Channels
┌──────────────┴──────────────────────┐
│    Android Native Bridge Layer      │
│  - DeviceChannelHandler             │
│  - NotificationChannelHandler       │
│  - CallChannelHandler               │
│  - FileChannelHandler               │
│  - StateEventChannel                │
└──────────────┬──────────────────────┘
               │
┌──────────────┴──────────────────────┐
│   Existing Kotlin Modules (已完成)  │
│  - DeviceManager                    │
│  - TcpClient/TcpServer              │
│  - PairingManager                   │
│  - DeviceRepository                 │
└─────────────────────────────────────┘
```

### 1.4 Platform Channels 定义

| Channel 名称 | 类型 | 用途 |
|-------------|------|------|
| `com.smslink/device` | MethodChannel | 设备管理（配对、连接、断开、角色切换） |
| `com.smslink/notification` | MethodChannel | 通知同步 |
| `com.smslink/call` | MethodChannel | 通话控制 |
| `com.smslink/file` | MethodChannel | 文件传输（支持最大 20GB，文件夹传输） |
| `com.smslink/state` | EventChannel | 状态监听（连接状态、角色变化、配对状态） |

**关键方法定义**:

**DeviceChannel**:
- `initialize(role: String)` - 初始化设备角色（PRIMARY/SECONDARY）
- `startDiscovery()` - 开始发现设备
- `stopDiscovery()` - 停止发现
- `connectToDevice(deviceId: String)` - 连接到设备
- `disconnect()` - 断开连接
- `sendPairingRequest(deviceId: String, code: String)` - 发送配对请求
- `switchRole(newRole: String)` - 切换设备角色（会触发其他设备角色变化）
- `getPairedDevices()` - 获取已配对设备列表（1主4副）

**StateChannel** (EventChannel):
- `connectionState` - 连接状态变化
- `discoveredDevices` - 发现的设备列表
- `pairingState` - 配对状态变化
- `roleChanged` - 角色变化通知

### 4.2 角色切换流程（优化版）

**触发方式**: 长按 AppBar 角色标签 3 秒

**确认对话框**:
```
┌─────────────────────────────────┐
│  ⚠️ 切换设备角色                │
│                                 │
│  当前: 主设备 → 副设备          │
│                                 │
│  切换后:                        │
│  • 当前连接将断开               │
│  • 其他副设备需要重新配对       │
│  • 如果有其他主设备，它将自动   │
│    变为副设备                   │
│                                 │
│  [取消] [确认切换]              │
└─────────────────────────────────┘
```

**角色切换逻辑**:

**场景 1**: 设备 1（主）、设备 2（副）、设备 3（副）
- 设备 2 切换为主设备
- 结果: 设备 1 自动变为副设备，设备 3 需要重新配对

**场景 2**: 设备 1（主）、设备 2（副）
- 设备 2 切换为主设备
- 结果: 设备 1 自动变为副设备

**实现细节**:
1. 用户确认切换后，发送角色切换消息到所有已连接设备
2. 原主设备收到消息后，自动切换为副设备
3. 未连接的副设备保持配对状态，但需要重新连接
4. 新主设备启动热点和 TCP 服务器
5. 原主设备（现副设备）自动尝试连接新主设备

## 8. 系统通知体系

### 8.1 通知渠道（5个独立渠道）

| 渠道 ID | 渠道名称 | 优先级 | 用途 | 声音 | 振动 |
|--------|---------|-------|------|------|------|
| `connection_status` | 连接状态 | LOW | 持续显示连接状态 | 否 | 否 |
| `mirrored_notifications` | 镜像通知 | DEFAULT | 同步的远程通知 | 是 | 是 |
| `incoming_call` | 来电提示 | HIGH | 来电通知 | 是 | 持续 |
| `file_transfer` | 文件传输 | DEFAULT | 文件传输进度 | 否 | 否 |
| `system_messages` | 系统消息 | HIGH | 角色切换、连接变化 | 是 | 是 |

### 8.2 连接状态通知（前台服务）

**显示时机**: 应用运行时持续显示

**已连接状态**:
```
🟢 SMS Link - 已连接
已连接到 "我的平板"
点击查看详情
```

**未连接状态**:
```
⚪ SMS Link - 未连接
等待设备连接...
点击打开应用
```

**重连中状态**:
```
🟡 SMS Link - 重连中
正在尝试连接到 "我的平板"...
点击查看详情
```

**特性**:
- 前台服务通知（不可关闭）
- LOW 优先级（不打扰用户）
- 点击跳转到首页
- 实时更新连接状态
- 显示连接时长（已连接状态）

### 8.3 镜像通知

**标题格式**: `[来源设备] 应用名`

**示例**:
```
[我的平板] 微信
张三: 明天见
```

**特性**:
- DEFAULT 优先级
- 点击跳转到通知历史页
- 支持展开查看完整内容
- 显示应用图标
- 支持通知操作（如果原通知有）
- 自动分组（按应用）

**通知样式**:
- BigTextStyle（长文本）
- BigPictureStyle（图片通知）
- InboxStyle（多条消息）

### 8.4 来电通知

**显示策略**: 全屏优先

**锁屏状态**: 全屏 Activity（类原生来电界面）

**应用使用中**: 全屏 Activity 覆盖当前页面

**通知内容**:
```
📞 来电 - 138****1234
来自 "我的平板"
[接听] [挂断]
```

**特性**:
- HIGH 优先级
- 全屏意图（Full-Screen Intent）
- 持续振动
- 来电铃声
- 不跳转（直接在通知中操作）
- 支持快速回复（拒接并发送短信）

**快速回复选项**:
- "我在忙，稍后回复"
- "我在开会"
- "我在开车"
- 自定义回复

### 8.5 文件传输通知

**三阶段通知**:

**阶段 1: 接收请求**
```
📁 文件传输请求
"我的平板" 想发送 "报告.pdf" (2.3 MB)
[接受] [拒绝]
```

**阶段 2: 传输中**
```
📁 正在接收文件
报告.pdf - 45% (1.0/2.3 MB)
预计剩余 15秒
[暂停] [取消]
```

**阶段 3: 完成**
```
✓ 文件接收完成
报告.pdf (2.3 MB)
[打开] [查看位置]
```

**失败状态**:
```
✗ 文件传输失败
报告.pdf (2.3 MB)
错误: 连接中断
[重试] [删除]
```

**特性**:
- DEFAULT 优先级
- 点击跳转到文件传输页
- 显示实时进度条
- 支持暂停/恢复/取消
- 完成后自动消失（5秒）或点击操作

### 8.6 角色切换通知

**内容**:
```
⚠️ 角色已切换
已从 "主设备" 切换到 "副设备"
所有连接已断开，请重新配对
```

**特性**:
- HIGH 优先级
- 5秒后自动消失
- 点击跳转到首页
- 显示角色切换图标

### 8.7 连接状态变化通知

**连接成功**:
```

正在尝试连接到 "我的平板"...
```

**配对成功**:
```
✓ 配对成功
已成功配对 "我的平板"
```

**配对失败**:
```
✗ 配对失败
配对码不正确或已过期
[重试]
```

**特性**:
- HIGH 优先级
- 5秒后自动消失
- 点击跳转到首页
- 失败时提供重试按钮

### 8.8 通知权限请求策略

**渐进式请求**:

3. **首次通话**: 请求电话权限
4. **首次文件传输**: 请求存储权限

**权限请求对话框**:

```
┌─────────────────────────────────────┐

└─────────────────────────────────────┘
```

**权限被拒绝后**:
- 不再自动弹出
- 在设置页显示"未授予"状态
- 提供"授予"按钮跳转到系统设置
